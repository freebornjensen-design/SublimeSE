# Space Engineers для Sublime Text 4

Пакет для скриптов программируемого блока: автокомплит и линтер на компиляторе самой игры плюс веб-симулятор,
чтобы отлаживать скрипт без переключения в игру.

## Установка

Нужны Sublime Text 4, установленная Space Engineers и .NET Framework 4.8 (есть в Windows 10). .NET SDK не нужен:
хелпер собирается компилятором Roslyn, который лежит в `Bin64` игры.

```powershell
powershell -ExecutionPolicy Bypass -File D:\Projects\SE\SublimeSE\install.ps1
```

Скрипт собирает `SeHelper.exe` и копирует пакет в `Packages\SpaceEngineers` каждого существующего профиля:
`%APPDATA%\Sublime Text` и `%APPDATA%\Sublime Text 3`. ST4, обновлённый с ST3, продолжает жить во втором.
Проверить, какой профиль взял Sublime, можно в консоли (View → Show Console): плагин пишет туда путь к пакету.
После правок в репозитории запусти его ещё раз. Если игра стоит не там, где по умолчанию: `install.ps1 -Bin64 "E:\Steam\...\Bin64"`
и `"game_bin64"` в настройках пакета.

## Что умеет редактор

Скриптом SE считается `.cs`, в котором встречаются `MyGridProgram`, `GridTerminalSystem`, `Main(string…)` и т. п.
Режим можно переключить вручную: «SE: Считать файл скриптом».

- **Автокомплит** по реальному API игры: члены после точки, типы, перегрузки, описания из XML-доков игры.
- **Линтер**: ошибки компилятора в режиме C# 6 (как в игре) и проверка **настоящего whitelist игры**. Хелпер при старте
  собирает его тем же кодом, что игра (`VRage.Scripting` + `MySpaceGameDefaultIlChecker`, плюс чёрный список
  из `MySandboxGame`), и проверяет скрипт её же анализатором. Поэтому `Path.Combine` проходит, а `Path.GetTempFileName`,
  `System.Tuple`, `Stopwatch` и `Regex.CacheSize` нет, ровно как в игре. Подчёркивание, текст ошибки в конце строки,
  счётчик в статус-баре, «SE: Список ошибок». Запрещённое не показывается в автокомплите и помечается в ховере.
- **Ховер**: сигнатура, описание, параметры, пометка «запрещено whitelist'ом».
- **Скопировать код для игры** (`Ctrl+Alt+C`): из файла-шаблона VSC-SE берётся код между регионами Prelude,
  проверяется лимит в 100 000 символов.

### Аббревиатуры (как в Emmet): пишешь в начале строки и жмёшь Tab

| Ввод | Результат |
|---|---|
| `gbt:IMyBatteryBlock` | `List<IMyBatteryBlock> batteries` + `GetBlocksOfType(...)` |
| `gbt:IMyThrust:engines` | то же, со своим именем переменной |
| `gbn:IMyTextPanel:LCD Main` | `GetBlockWithName("LCD Main") as IMyTextPanel` |
| `gbg:IMyDoor:Airlock` | блоки из группы |
| `lcd:Status LCD` | поверхность LCD + `WriteText` |
| `upd:10` / `upd:once` | `Runtime.UpdateFrequency = …` |
| `fe:batteries` | `foreach (var battery in batteries)` |
| `echo:x,y` | `Echo($"x: {x}, y: {y}")` |
| `ini` / `prop:Velocity:float` / `act:OnOff_On` | MyIni, SetValue, ApplyAction |

### Doc-комментарии (как в DocBlockr)

`///` над методом разворачивается в `<summary>`, `<param>` по параметрам и `<returns>`, если метод не void.
Enter внутри `///` продолжает комментарий.

### Сниппеты

`sepb` (каркас Program/Save/Main), `sestate` (конечный автомат на yield), `seigc`, `sesprite`, `sebar`.

## Симулятор

`Ctrl+Alt+S` или «SE: Открыть симулятор» открывает в браузере `http://127.0.0.1:8765/`.
При каждом сохранении скрипт перекомпилируется и перезапускается (Storage сохраняется через `Save()`, как в игре).

- **Сетка**: «Импорт блупринта» из `%AppData%\SpaceEngineers\Blueprints\local`. Берутся терминальные блоки
  с именами, группами, CustomData, зарядом батарей и содержимым контейнеров. Ёмкости батарей, баков
  и инвентарей подтягиваются из определений игры. Блоки можно добавлять и удалять, состояние сохраняется
  в `<скрипт>.se-grid.json` рядом со скриптом («Сохранить сетку» запоминает начальное состояние для «Сброса»).
- **Схема**: карточки блоков с вкл/выкл, процентными шкалами (заряд, заполнение инвентаря, баки, поршни,
  двери, роторы, тяга) и чипами состояний; группировка по типу, группам или сеткам.
- **Инспектор**: все свойства интерфейса блока, редактируемые вживую, плюс поля симуляции
  (нагрузка сети и внешнее питание для батарей, приток газа для баков), инвентарь, CustomData, группы, экраны.
- **Время**: пуск/пауза (Пробел), шаг на 1/10/100 тиков, скорость ×0.1…×10, `UpdateFrequency` как в игре
  (Update1/10/100/Once), «Выполнить» с аргументом (`UpdateType.Terminal`).
- **Экраны**: текст LCD с размером шрифта, цветами и выравниванием; Echo программируемого блока.
- **Спрайты**: кадры `DrawFrame()` рисуются на canvas: текстуры игры (BC7/DXT из `Content\Textures` хелпер
  декодирует в PNG), иконки предметов (`"MyObjectBuilder_Ore/Iron"`), тонировка цветом, поворот, выравнивание,
  `CreateClipRect`, текстовые спрайты. Если спрайты рисуются, а `ContentType` не `SCRIPT`, экран об этом предупредит:
  в игре их не было бы видно. Пример: `examples/SpriteDashboard.cs`.
- **Ошибки**: исключение останавливает скрипт, как в игре, и показывает строку; зависание дольше 3 с
  ловит сторож.

### Чего пока нет

- Шрифты текстовых спрайтов приблизительные (системный шрифт вместо игрового Debug/Monospace), поэтому ширина строк
  чуть отличается. Скрипты фона `surface.Script` (встроенные экраны игры) не рисуются.
- IGC и таймеры только заглушки: таймер пишет «сработал» в журнал, но действия тулбара не выполняет.
- Счётчик инструкций не считается, вместо него время запуска. Моки на `RealProxy` медленнее игры, так что
  миллисекунды завышены.
- Если после обновления игры whitelist собрать не удастся (поменялись внутренние классы), линтер переключится
  на приблизительные правила по пространствам имён. Какой whitelist сейчас используется, видно в `/api/ping`
  (поле `whitelist`).
- Поведение есть у батарей, баков, поршней, роторов, дверей, двигателей, коннекторов, шасси и таймеров.
  У остальных блоков свойства просто хранятся и редактируются.

## Устройство

```
helper/src/*.cs      SeHelper.exe: Roslyn игры, whitelist игры (GameWhitelist.cs), моки API (RealProxy), симуляция, HTTP на 127.0.0.1
helper/build.ps1     сборка хелпера компилятором из Bin64 игры
package/SpaceEngineers/
  se_plugin.py       плагин Sublime (Python 3.8+): LSP-подобный клиент хелпера, команды, аббревиатуры
  web/               GUI симулятора (vanilla JS)
  snippets/, templates/, *.sublime-*
examples/StatusMonitor.cs   пример скрипта
```
